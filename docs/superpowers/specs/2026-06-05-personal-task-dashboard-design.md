> агенти закривають задачі через `Status=Done`, не видаляють; видалення рядків — вручну в UI.

## Мета
Єдине місце керування задачами по всіх сферах: **проєкти + побут + бюрократія**.
Доступ із десктопа і телефона. Частину задач створюють/закривають агенти команди.

## Критичні рішення (і чому саме так)
1. **Не будуємо застосунок — конфігуруємо Notion.** Персональний таск-менеджер на
   одну людину — найвирішеніша проблема в софті. Кастомний веб-апп = тижні роботи
   Pixel+Forge + вічна підтримка + лише десктоп (побутові/бюрократичні задачі
   додаються з телефона). Notion уже підключений через MCP і працює на телефоні.
2. **Корінь проблеми — фрагментація, а не брак інструмента.** У просторі
   «Andriy Leso's Space HQ» знайдено ДВІ бази задач (`Todo List` і `My Tasks`)
   плюс дефолтний шаблон. Дашборд тут — не новий софт, а наведення ладу.
3. **Survivor = `My Tasks`.** Це системна Tasks-база Notion (живить вкладку Home,
   уже має поле `Source`). Робимо її єдиним джерелом правди.
4. **`Todo List` = 100% шаблонне сміття.** Зріз вмісту: лише туторіал-рядки
   («Click the blue New button…», «Check the box to mark items as done», «Example
   sub-page»…). Живих задач нема → мігрувати нема чого, просто архів.

  (data source `collection://32670990-6f28-80a7-abfd-000bf4287813`). 0 живих задач — безпечно й оборотно (йде в кошик Notion).

- **A3.** Прибрати порожню сторінку-обгортку `To Do List` (parent шаблону), якщо в ній нема корисного.
- **Критерій готовності:** у просторі лишається РІВНО одна база задач.

**Результат виконання (2026-06-05):**

## Ризики та межі (чесно)
- `My Tasks` — системна база Notion; якщо на v2 її схему не вийде редагувати через
  API, консолідуємо на звичайну редаговану базу (рішення на етапі впровадження).
- **Свіжість даних:** дашборд живий рівно поки дані свіжі. Автоматика (v4) допомагає
  лише ПРОЄКТНОМУ домену. **Побут і бюрократія = ручний ввід** з телефона — за дизайном.
- Виконавець — команда (найближче Forge: інтеграції/доки), не Bill.
